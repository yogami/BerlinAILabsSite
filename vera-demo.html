VERA Protocol: Client-Side Proof-of-Execution (PoE) Simulator

Cryptographic Execution Receipts in Browser WebCrypto

Edit the tool-call JSON payload below and run the verifier. Your browser generates a fresh 128-bit nonce, hashes the canonical envelope with SHA-256, signs the receipt with an ephemeral ECDSA P-256 keypair, and verifies the signature locally.

1
⚡ Action Envelope

Canonical Tool Intent & Nonce Generation

The harness binds the tool invocation arguments to a CSPRNG 128-bit nonce and ISO-8601 timestamp to prevent replay attacks.

→ Payload: {"tool":"stripe_charge","amount_eur":420} Nonce (128-bit): Waiting for WebCrypto...
2
📝 Proof of Execution

SHA-256 Digest & ECDSA P-256 Signature

window.crypto.subtle computes the SHA-256 digest of the canonical envelope and signs it with an ephemeral ECDSA P-256 private key (production specification supports Ed25519 and post-quantum ML-DSA-65).

→ SHA-256 Digest: computing... ✓ ECDSA Signature: computing...
3
📡 Peer Verification

Public-Key Verification & Audit Append

An independent verifier checks the signature against the agent's public key JWK via crypto.subtle.verify() before appending the receipt to the hash-chained audit log.

→ Public Key JWK (x): computing... ✓ crypto.subtle.verify(): waiting...
4
⭐ Trust Accounting

Deterministic Reputation Update

Upon valid cryptographic verification, the local state machine increments the agent's verified execution count and updates its bounded trust score.

→ Verified Receipts in Session: 0 ★ Trust Score: 0.650 -> 0.720 (+0.070)
